# Maintenance

## Verification gates (run after every change)

```bash
cd ~/.pi
npx tsc --noEmit | grep -v pi-cbm     # must print nothing (pi-cbm is a known pre-existing baseline error)
npx eslint agent/extensions/pi-tool-display/
```

Live check: `/reload`, then `/tool-display` (flag state), then run one tool per path —
`read`, `bash`, `powershell`, `ffgrep`, `fffind`, `recall`, `git_status`, `write`, `edit`.

There is no unit-test harness for this extension (offline: `tsx` is not installable), so verification
is compile + lint + a manual render pass.

## Upstream sync

**pi-tool-display (upstream fork point: `0.5.0`)**

- `bash-display.ts` and `diff-renderer.ts` are upstream **verbatim** (one unused-import prune in
  `diff-renderer.ts`). Compare file-by-file against a fresh `npm pack pi-tool-display@<newer>` and
  cherry-pick deliberately; record each delta in `FORK.md`.
- Never reinstall the npm package: `agent/settings.json` packages and `agent/npm/package.json` must
  stay free of `pi-tool-display` (the local directory is the only copy). If `install.sh` /
  `.script/update.sh` re-adds it, that is a bug in the updater — fix the allowlist there.
- `agent/npm/node_modules/pi-tool-display` must not exist.

**pi-style (vendored version: `@quandev104/pi-style@0.2.11`)**

- Re-port = re-run the `npm pack` + `cp` steps in `INTEGRATION.md`, then re-apply the six
  dead-declaration removals until `tsc` is clean, then re-apply the card-background delta
  (`TOOL_CARD_BG_HEX` fill in `shared/box.ts` + the same base in `split-diff.ts`).
- `pistyle-bridge.ts` and `pistyle-tool-patch.ts` are version-independent and must **not** be
  regenerated by a re-port.
- Keep the port surface to `features/tools/boxed/*` + `shared/{ansi,box,elapsed,render-budget,split-diff,theme-extras}`.
  Do not start pulling in `pi/`, `app/`, `domain/`, `features/messages`, `features/editor`,
  `features/status-line` — those surfaces belong to `pi-zentui` in this setup.

## Open items / known gaps

1. **`collapseAfterTurn` only works in pi-style mode.** It is mapped into pi-style's session config;
   the compact path has no collapse implementation (the home-grown one was removed as duplication).
2. **pi-style's message-boundary resets are not ported.** Their coordinator clears per-call registries
   on message boundaries; here they reset only on session start/shutdown. Long sessions with thousands
   of tool calls keep those maps alive until then. If memory ever matters, wire a message-boundary
   reset to `resetPistyleRegistries()`.
3. **`fff-multi-grep` uses the boxed fallback card.** Its args are `{ patterns: [...] }`, which no
   pi-style renderer parses. An adapter could synthesise a `pattern` string and route it to the grep
   renderer — deliberately not done (would be a hand-rolled invention again).
4. **pi-style's `git.ts` / `gh.ts` cards are only reachable through the `bash` renderer's command
   parsing.** The `git_*` tool family renders as fallback cards.
5. **The patch is unversioned.** pi-style certifies its core patches against recorded fingerprints;
   this fork only checks that the prototype methods exist. If pi renames them, `install()` returns
   `false` silently and only the registration seams remain. Consider surfacing that via
   `logToolDisplayDebug` or a startup warning.
6. **`config.json` drift.** It was reset to defaults once during testing. Watch for a repeat; if it
   happens, capture the modal/preset action that caused it.

## Do not touch (owned elsewhere)

- `agent/zentui.json` — zentui owns the editor, footer, user messages and selector borders. The whole
  point of this fork is that pi-style's tool cards do not disturb it.
- `agent/themes/**`, `agent/settings.json` (packages/theme), `agent/npm/**` — not part of this
  extension's work.
- `agent/db-config.json`, `agent/auth.json`, `.env*`, `agent/models.json`, `agent/9router-config.json`
  — secrets/config; never read values into logs or docs.
- Other extensions' directories (`pi-cbm`, `filechanges`, `bash-guard`, …) — the `pi-cbm` compile
  error is a known, out-of-scope baseline.

## Reviewer checklist for a change here

1. Does it keep the compact path byte-identical to upstream when `boxedToolCalls` is off?
2. Does it add any per-render I/O, allocation or timer? (It should not.)
3. Does it use only theme tokens that exist in pi's theme schema **and** `tokyo-night.json`?
4. Is every deliberate delta from upstream recorded in `FORK.md`?
5. Does it touch `src/pistyle/**` without a re-port reason? (Vendored code should stay pristine.)
