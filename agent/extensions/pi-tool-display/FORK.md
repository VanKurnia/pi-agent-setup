Modules merged 2026-09-30: the boot-time module graph was flattened from 46 files to 8. Pi loads extensions through jiti at roughly 19 ms per module regardless of size, so the 46-module layout cost more than the 515 KB it carried; merging `pistyle/shared/*` (6 -> `shared/index.ts`), `pistyle/features/tools/boxed/*` (18 -> `boxed/index.ts`), `user-message-box*` (5 -> 1), the three fork cards (3 -> `fork-cards.ts`), the support modules (7 -> `support.ts`) and the core wiring (5 -> `wiring.ts`) cut this extension's load from 2,161 ms to ~297 ms. Byte volume is unchanged, so the future upstream/pi-style re-port steps now land inside a merged file: find the `// from: <pi-style module>` section marker and edit inside it. Collisions introduced by the shared scope were resolved by renaming (the dispatcher became `renderBoxedToolForCall`/`ForResult` so it stops shadowing pi-style's box helpers; `lsDisplayPath`, `renderGrepErrorLines`, `readSubagentRows`) or by collapsing byte-identical duplicates.

Compact path removed 2026-09-30: `pistyle-tool-patch.ts` already bypassed every renderer this extension registered whenever `boxedToolCalls` was on, so the compact path was unreachable in practice while carrying ~190 KB. Deleted `src/tool-overrides.ts`, `bash-display.ts`, `diff-renderer.ts`, `diff-presentation.ts`, `line-width-safety.ts`, `pending-diff-preview.ts` and `write-display-utils.ts`. What survived from `tool-overrides.ts` — the `pi-tool-display.api.v1` global, the `pi.registerTool` interception and MCP model-facing metadata (label, description, promptSnippet/Guidelines, parameters, prepareArguments) — moved to `src/tool-decoration.ts`; `decorateTool` now attaches renderers only when the caller supplies them in an adapter. `capabilities.ts` went with it, because its only job was guarding compact-path config fields against detected RTK/MCP tooling. `tool-display-api-consumer.{js,d.ts}` was deleted: it had no importer in this repo (the global API it wraps is still published). Config shrank to the five fields the boxed path reads — `enabled`, `enableNativeUserMessageBox`, `collapseAfterTurn`, `previewLines`, `expandedPreviewMaxLines` — so `boxedToolCalls`, `registerToolOverrides`, `customToolOverrides`, `read/search/mcpOutputMode`, `bash*`, `diff*`, `showTruncationHints` and `showRtkCompactionHints` are gone from the schema, `presets.ts` and the `/tool-display` modal. `normalizeToolDisplayConfig` ignores unknown keys, so existing `config.json` files still load; the stale keys are simply dropped on the next save. Presets now differ only in `previewLines` / `expandedPreviewMaxLines` (opencode 8/4000, balanced 12/8000, verbose 20/20000).
